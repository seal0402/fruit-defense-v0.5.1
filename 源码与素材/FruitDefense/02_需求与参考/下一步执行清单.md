## 我接下来做什么

### 第一步：建立正式Godot工程

在现有game目录下创建与已验证工具版本匹配的工程、C#配置、主场景和启动入口。分开组织战场、射手、弹药、敌人、隔离网、水晶和界面。让用户能从明确的入口启动原型，并能找到关键源码。

### 第二步：完成占位场景与基本输入

建立敌人上方出现、战场、底部隔离网、射手选择区和水晶的布局。先用临时形状区分角色与对象，实现点击切换、待命或恢复显示、拉弓瞄准、力度限制、释放发射以及取消瞄准。

### 第三步：实现三种基础攻击

- 普通弹药：中等射程，首次命中结束，射手恢复较快。
- 狙击弹药：远程，整个射程可贯穿多个敌人，每发弹药对每个敌人最多结算一次。
- 霰弹：短程，高额直击伤害加命中点周围一格的溅射。

角色恢复、弹药寿命、最大射程、伤害和飞行速度分别管理。其他弹药仍在飞行时，可以切换待命射手继续发射。命中结果、受击提示、伤害和死亡同步处理。

### 第四步：实现敌人与防守规则

敌人向下移动，接触完整隔离网后按间隔攻击。隔离网归零后解除阻挡，敌人继续向水晶移动。触碰水晶的每只敌人只扣1点核心生命，随后退出战斗。被击杀的敌人不会再造成入侵伤害。

### 第五步：完成一关流程

加入可配置的有限波次、击杀积分、核心生命、隔离网血量、暂停、胜负和重开。第一关用3类射手、1类敌人验证整个循环，技能卡槽保持预留。原型结束条件先按策划中的开发建议验证。

### 第六步：检查并交付原型

编译、启动并实际操作原型，核对弹射、切换、恢复、三种伤害、敌人阻挡、防线破碎、核心扣血、积分与重开。数值和手感根据实际运行调整。整理运行入口、预览、源码阅读说明和已知问题。

## 原型验收标准

| 检查项 | 预期结果 |
| --- | --- |
| 角色选择 | 切换后发射对应类型弹药 |
| 独立恢复 | 一个射手恢复期间，其他待命射手仍可使用 |
| 普通攻击 | 命中敌人造成伤害并结束弹药 |
| 狙击攻击 | 贯穿多个敌人，每个敌人每发只受一次伤害 |
| 霰弹攻击 | 直击与周边溅射按配置准确结算 |
| 射程 | 狙击最远、普通约3/4、霰弹约1/4；离开发射有效范围后正确结束 |
| 隔离网 | 只承受按攻击间隔产生的敌方伤害，归零后破碎 |
| 核心 | 敌人触碰水晶才扣1点，每只只结算一次 |
| 胜负 | 核心归零失败；有限波次完成且核心存活时按原型规则胜利 |
| 重开 | 血量、积分、波次、敌人、弹药和射手恢复状态全部正确重置 |
| 技能位置 | 留有扩展位置，普通攻击三种类型不依赖技能系统 |
