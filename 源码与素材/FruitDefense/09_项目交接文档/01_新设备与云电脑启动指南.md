# 新设备与云电脑启动指南

## 先识别环境

系统未知时不要先运行.exe。让云端AI报告系统、CPU、是否有桌面、可用空间和网络。

Linux/macOS可执行：

```bash
uname -s
uname -m
command -v python3
command -v dotnet
printenv DISPLAY
df -h .
```

Windows PowerShell可执行：

```powershell
[Environment]::OSVersion
[Environment]::Is64BitOperatingSystem
Get-Command dotnet -ErrorAction SilentlyContinue
Get-PSDrive -PSProvider FileSystem
```

固定版本见tools/platform-manifest.json。它记录官方URL与SHA512；初始化前验证下载内容。不要以普通Godot替代.NET版本，也不要以.NET Runtime替代SDK。

## Windows x64：离线包

1. 解压Windows完整离线开发包。保持FruitDefense和offline-tools为同级目录。
2. 进入FruitDefense，双击“初始化开发环境.cmd”。它验证两个原始压缩包，再解压到tools/dotnet与tools/godot。
3. 双击“检查开发环境.cmd”确认版本。
4. 双击“启动保卫水果.cmd”试玩，或“打开Godot工程.cmd”继续开发。
5. “运行全部检查.cmd”执行规则及图形输入检查，需要可用的Windows图形会话。

初始化不修改系统PATH，不要求安装到D盘。首次解压可能较慢。工具目录若已有内容而没有完成标记，脚本停止供检查，不会自动删除或覆盖整个目录。

## Windows：通用包联网安装

在FruitDefense目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Project.ps1 -Action Setup -Download
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Project.ps1 -Action Doctor
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Project.ps1 -Action Build
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Project.ps1 -Action Test -RulesOnly
```

若已安装正确工具，可在当前终端设置路径，指向实际可执行文件：

```powershell
$env:FRUITDEFENSE_DOTNET = 'C:\Tools\dotnet\dotnet.exe'
$env:FRUITDEFENSE_GODOT = 'C:\Tools\Godot\Godot_v4.7.2-stable_mono_win64.exe'
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Project.ps1 -Action Doctor
```

本机兼容逻辑会尝试原来的D:/GodotDev，但这不是必要依赖。设置FRUITDEFENSE_PORTABLE_ONLY=1可关闭该兼容查找，用于严格迁移验证。

## Linux x64/ARM64与macOS

需要Python 3.9以上、Bash及解压工具。项目初始化只下载并解压工具，不自动更改系统包或申请管理员权限。

```bash
cd /path/to/FruitDefense
python3 tools/setup.py --check-only
python3 tools/setup.py --download
bash tools/project.sh doctor
bash tools/project.sh build
bash tools/project.sh test
bash tools/project.sh import
```

setup.py根据操作系统与CPU选择固定官方包并校验SHA512。Linux默认使用标准glibc发行版的工具；Alpine/musl、特殊架构或受限容器需要另行确认支持。不要直接复制Windows的dotnet.exe到Linux。

使用已有工具时：

```bash
export FRUITDEFENSE_DOTNET="/absolute/path/to/dotnet"
export FRUITDEFENSE_GODOT="/absolute/path/to/Godot.NET.binary"
bash tools/project.sh doctor
```

macOS的Godot位于.app内部，路径通常以Contents/MacOS/Godot结尾。系统首次打开官方下载应用可能要求用户在系统界面确认来源；本项目不自动关闭系统安全检查。

## 有桌面的云电脑

```bash
bash tools/project.sh play
bash tools/project.sh editor
bash tools/project.sh test-ui
```

Linux需要图形显示会话与可用的兼容OpenGL渲染；中文界面还需要可用的CJK字体。若云镜像缺少这些依赖，按其发行版与权限补充。可用虚拟显示时再考虑Xvfb，不能把普通headless运行的空白图片当作画面验证。

## 无桌面的云电脑

仍可阅读、改源码、编译、运行21项核心规则检查，或以Godot的headless模式导入项目。界面检查含真实渲染与截图，不应使用headless强行通过。报告“规则已验证、界面等待有显示环境验证”，保留原有Windows截图供参考。

## 缓存和路径

- tools/packages：已附带Godot C#所需NuGet包，game/NuGet.Config使用相对路径。
- .local：当前机器生成的.NET缓存与NuGet缓存。
- game/.godot：Godot导入和编译产物。
- tools/dotnet、tools/godot、tools/downloads：当前机器的工具和下载文件。
- 这些生成目录不属于通用源码包，也不应作为跨系统缓存复制。
